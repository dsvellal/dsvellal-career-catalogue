# UI Screen Design — Data Representation Architecture

> **Current implementation (2026-08-06): Journey Atlas.** The eight views and privacy rules below supersede the legacy graph-first mockups later in this document. Legacy components remain in the source tree for reference but are not routed by `App.tsx`.

## Journey Atlas — Current Eight-View Projection

The atlas uses one evidence vocabulary across all views: Tier A (corroborated), Tier B (documented), Tier C (self-reported), and derived synthesis. Caveat labels stay beside claims. Visual encodings explain scope and progression, but never imply statistical causality, uninterrupted skill use, psychometric rank, or sole attribution.

| # | View / hash | Primary visual | Projection job | Interpretation boundary |
|---|-------------|----------------|----------------|-------------------------|
| 1 | Executive Portrait `#portrait` | Editorial portrait, proof-point grid, four-mode operating system | Establish Datta as engineer, translator, multiplier, and steward | Resume-originated figures remain self-reported unless independently corroborated |
| 2 | Twenty-Year Journey `#journey` | Three-strand braided timeline plus era cards | Show work, service, and learning developing in parallel from 2007–2026 | Line proximity is narrative continuity, not causality |
| 3 | Capability Compounder `#capabilities` | Capability river and current-signature matrix | Show capabilities being reinvested into progressively broader leverage | Stream length means presence in dated evidence; ordinal levels are not psychometric scores |
| 4 | Outcome Ledger `#outcomes` | Leverage ladder and quantified ledger | Separate individual craft, team enablement, organizational systems, and enterprise/community value | Shared outcomes are contributions, not claims of sole credit |
| 5 | Trust & Respect `#respect` | Attributed-voice timeline and summary metrics | Let colleagues' direct words validate technical credibility, calm leadership, and generosity | Selected recommendations are evidence, not an unbiased survey |
| 6 | Influence Web `#influence` | Credibility → mechanism → reach flow | Explain how coaching, facilitation, standards, and community make expertise reusable | A structured narrative flow, not a raw social graph or causal model |
| 7 | Teaching & Service Ripple `#service` | Concentric reach rings plus program stream | Present sustained teaching and service as a parallel career lane | Rings are categorical, not proportional area; reach claims retain their evidence tier |
| 8 | Momentum & Next Horizon `#momentum` | Dated evidence-signal curve and horizon vectors | Show the AI-native and regulated-software direction already visible in current work | Evidence count is a documentation signal; horizons are aspirations, not forecasts |

### Why this sequence

The narrative first gives visitors a concise identity, then earns breadth through chronology and demonstrated capability. Quantified outcomes establish value; direct voices establish trust independently of self-description. Only then does the atlas frame influence and service, finishing with evidence-grounded momentum. This ordering is persuasive because it separates assertion, delivery, external validation, multiplication, and aspiration instead of collapsing all five into a single heroic claim.

### Navigation and responsive behavior

- Stable hashes make every view shareable and browser-history friendly.
- Desktop navigation exposes eight links with `aria-current`; Left/Right/Home/End move focus across them.
- At 900 px and below, the tab strip becomes a labeled native select; layouts progressively collapse to one column by 680 px.
- Horizontally dense visuals are keyboard-focusable scroll regions. SVG charts provide `<title>` and `<desc>` text; decorative flow links are hidden from assistive technology.
- Visible focus styles, reduced-motion handling, print rules, and scroll-to-top on view changes are built into the shell.

### Public-build privacy boundary

Vite's `publicDir` is disabled. The logo and headshot are the only legacy public assets needed by the atlas and are imported explicitly into the module graph. The local `viz/public/data/evidence` symlink is therefore inert during production builds: raw evidence, email text, donor information, relationship exports, full vectors, and local evidence filenames do not enter `viz/dist`. Evidence references in the UI use opaque public source IDs and are provenance labels, not public raw-artifact fetches.

### Current Journey Atlas data contract

`viz/src/data/journey.json` is generated by `scripts/build_journey_data.py`; it is not the raw graph in a different shape. The top-level fields map editorially reviewed evidence into the eight views:

| Data key | Primary consumers |
|----------|-------------------|
| `thesis`, `headline_metrics` | Executive Portrait |
| `eras`, `service_lane` | Twenty-Year Journey |
| `capability_streams` | Journey, Capability Compounder, Influence Web |
| `impact_ledger` | Outcome Ledger |
| `respect` | Trust & Respect |
| `influence` | Influence Web |
| `teaching_service` | Teaching & Service Ripple |
| `momentum` | Momentum & Next Horizon |
| `caveats` | Shared interpretation-boundary tooltips and labels |

The builder's private intermediate reference contains a local evidence path long enough to validate file existence. The emitted public reference contains only `source_id`, `tier`, `supports`, and an optional year; each source-bearing claim can add `caveat_labels`. The browser displays the tier and source count, while native disclosure controls make support and caveat explanations available to mouse, keyboard, and touch users. The analysis companion, `data/journey-analysis.md`, records the thesis and why this projection is faithful to the underlying journey.

## Legacy Graph-First Design Principles (Archived)

1. **Curated highlights + drill-down (progressive disclosure)** — Show the most impressive numbers first, then let users explore deeper
2. **Three-level depth: Summary -> Rich Summary -> Full Artifact ("Explore the full story")** — Every data point can be expanded twice
3. **Reverse chronological everywhere** — Philips USA -> Philips India -> Amazon -> Exeter -> IBM, Independent last
4. **Evidence traceability** — Every data point traces to a source markdown file in `data/evidence/`
5. **Static pre-built JSON via `twin publish`** — No runtime server dependency for portfolio; all data baked at build time
6. **Rich data: maximize information density without overwhelming** — Dense but scannable

### Level Rendering Rules

| Level | Trigger | Data Used | UI Treatment |
|-------|---------|-----------|--------------|
| **Level 1: Summary** | Default display | `title`, `stat`, `type`, `era`, `date`, `summary` | Single row/card. Icon + title + date badge + type badge + era color accent |
| **Level 2: Rich Summary** | Click on Level 1 item | `rich_summary.*` | Expanded inline panel or slide-in panel. Narrative paragraph, metrics grid, quote blocks, evidence file links, skill tags |
| **Level 3: Full Artifact** | "Explore the full story" button in Level 2 | Fetch + render `evidence_file` path | Full-screen overlay or dedicated page. Complete evidence markdown rendered with headings, images, code blocks, tables. Back button returns to previous state |

### Legacy Evidence File Fetching (Disabled)

> The current public build does not fetch or copy raw evidence. The behavior below records the previous design only and must not be re-enabled without an explicit privacy review and curated publication allow-list.

Level 3 fetches the evidence markdown file and renders it directly:

```
GET /data/evidence/2020/individual/091-iwillcode-feedback.md
```

The legacy portfolio build copied evidence markdown into `viz/public/data/evidence/`. The current Vite configuration sets `publicDir: false`, so that local symlink is not copied and the current UI has no full-artifact renderer. The former design expected:
- Proper heading hierarchy
- Block quotes styled as testimonials
- Code blocks with syntax highlighting
- Images rendered inline (relative paths resolved)
- Tables rendered as HTML tables
- Links preserved and clickable
