## Key Quotes (Verbatim Feedback)

### Three Key Learnings:

> "Deduplicate test code. Create APIs that have what you want and don't be limited by what you get. Tests should focus on functionality rather than implementation design."

> "Consider having unit tests focus on behavior rather than structure."

> "Think of behaviors when coding unit tests. Be careful of coupling of unit test implementation to class implementation. Write understandable code to help with new joiners"

> "1. Good to see Rhythm code analyzed with other experienced programmers and get feedback. 2. Writing effective unit testing. 3. TDD techniques when prototyping before actual design in place."

### Suggestions to Improve:

> "More often to more folks! We all need to learn this."

> "Before the meeting, ask participants to have a juicy code examples ready to go."

> "Wrap up about 10 to 15 minutes before the end of the scheduled time, to debrief and capture action items."

> "It was little intimidating to see and evaluate code in real time. Preparation before the meeting could have helped by coming with clear agenda and code snippet discussion among internal colleagues before start. (NOTE: It ended really well and learned a lot)."

### What Went Well:

> "Good dialog using real examples."

> "Great topics. It took a while to get warmed up with juicy examples, but great discussion overall."

> "Engaging discussion driven by the participants."

> "Intimidation went away when it became clear we are here to help each other be better architects of software, and develop even better code that improves quality of Philips products in general but Ultrasound in particular. Experience of Datta, Simao and Ian to guide us and answer our questions was very insightful."

### Other Topics Requested:

> "Improving TICS historic trending on Rhythm. Merging best features from TICS and CodeScene. Deep dive into unit test behavior versus structure. Have a walk through of Dependency Injection tools to help manage test seam management at a macro level."

> "1. I would like to see good examples from other Philips teams regarding unit tests, TDD or other aspects of software development process like pair programming or extreme programming. 2. Take a concrete example from Ultrasound code base and make improvements while analyzing."
