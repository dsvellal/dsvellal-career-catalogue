## Slide 3: Coding Dojo: What is it?

- Dojo
- A safe place to practice.
- A place to make mistakes and learn.
- Get together to work on a Kata, have fun and engage in deliberate practice


## Slide 4: Coding Dojo: Goal

- Practice
- Learn techniques
- Improve techniques
- Not necessarily solve the problem


## Slide 5: Coding Dojo: Goal

- Safe environment
- New ideas are welcomed
- Collaborative / Non-competitive
- Open to all skill levels


## Slide 6: Coding Dojo: Principle

- The First rule of the dojo:
- You can’t discuss a technique without code
- You can’t show code without tests
- Code without tests simply doesn’t exist!
- Without tests, code simply does not exist


## Slide 7: Dojo Priciples: Mastery

- If it seems hard, find someone who can explain it.
- If it seems easy, explain to those who find it hard.
- No-one has mastery in all areas: everyone will both teach & learn.


## Slide 8: Coding Dojo : Don’t

- Rush to finish the problem
- Use a other problems
- Go into flame wars on discussions
- Compete with other participants
- Allow people to get lost


## Slide 9: Coding Dojo : Ethic

- If you know how to code, you should code
- If you're coding, everyone else has to understand what you're doing
- If you're the next to code, avoid breaking the flow
- If you're not coding,  don't disturb who is
- If you have an idea, show it with code
- If you're stuck, ask for help

## Slide 16: Collaborative game

- What is a Collaborative Game?
- You aim to beat the game itself
- Players help each other – they collaborate
- There are rules, activities and goals
- Why not competitive Game
- Learning happens more easily when you feel safe and relaxed


## Slide 17: Prepared Kata

- Show your best solution to a Code Kata
- The audience asks questions and gives feedback
- Everyone is learning - both presenter & audience


## Slide 18: Prepared Kata - Tips

- Practice many times before performance
- Keep it short!
- preferably under 30 minutes, not more than an hour
- Find a pair
- Explain each coding decision
- Expect that other and better solutions exist
- No need to follow advice at the time, note it for the retrospective


## Slide 19: Randori

- Another term from Karate - a free form interaction
- Everyone in the dojo contributes some code
- Show the code on a projector
- 60 - 90 minutes


## Slide 20: Randori – taking turns

## Slide 23: Randori Rules

- If you have the keyboard, you decide what to type.
- If you don’t know what to type, ask for help.
- If you are asked for help, kindly respond.
- If you are not asked, but see an opportunity for improvement, choose a wise moment to speak.


## Slide 24: Randori in Pairs

- Split the group into pairs (or trios)
- Each pair works on the same Kata
- A facilitator goes between pairs, helping them
- In the retrospective, share code and discuss how you wrote it


## Slide 25: Constraint Games

- Force yourself to code differently and test your limits
- Tool Constraints
- Design Constraints
- Social Constraints
