Abstract— In the programming world, understanding the dependencies between different components in a project is a common challenge faced by the developers because the conventional
methods that aid in managing the component dependencies require viewing and editing of a file, say a manifest file or a configuration file, which lists the dependencies in textual format.
This method may become cumbersome when the dependencies
grow. With Component-based architecture for the development
and delivery of software becoming the de-facto architecture
principle, where a software system is broken down into set of
collaborating (inter-linked) components and keeping in mind the
increasing demand for enriched user experience, the need of the
hour is to have a “Dependency management tool” that aids in
visualising and managing the component dependencies via a rich
GUI (Graphical User Interface)
Keywords— Dependency Management, GUI, Eclipse Modelling
Framework (EMF), Graphical Modelling Framework (GMF),
Simulation

I. INTRODUCTION
Understanding the dependencies between different components in a project is a common challenge faced by the developers. Conventionally, developers resort to the method of
manually going through a text file that maintains a list of dependent components. The adopted method becomes cumbersome when the dependencies increase. In such situations going through a huge list of entries in a text file to understand
the dependencies may not be the best possible solution.

B. Dependency Management
a) Addition of dependency – With the help of UI elements, addition of dependency is as simple as drawing a new
“dependency wire” between two components. The required
code for the above is generated by the underlying runtime.
b) Deletion of dependency – UI allows deletion of a component dependency by deleting a dependency wire that exists
between two components. The required code modifications
are done by the underlying runtime.
c) Editing of property – Properties like the name of the
project, version etc. are picked up from the manifest file or the
configuration file and projected via the UI component. The
user can edit them on via the UI. The edited values are updated accordingly by the runtime.
d) Following Best Practices – Using MVC architecture,
the runtime can be programmed to generate code which adheres to the best practices.
C. Plug-ability – A developer should be allowed to install
and use the “Dependency Management Tool” on top of any
Integrated Development Environments (IDEs).
II. MAIN RESULTS
The “Dependency Management Tool” can help in reducing
the development life cycle by improving
a) Dependency Visualisation,
b) Dependency Management and
c) Usability / Maintainability
by controlling the manual errors and enforcing best practices.

To address the above problem, “Dependency Visualisation”
was conceived, which allowed the developers to visualise the
dependencies of a component on other components. Work is
being done in this regard, and there are stable Dependency
Visualisation components that allow users to visualise the
dependencies.

A working prototype implemented in Java, using Eclipse
Modelling Framework (EMF) and Graphical Modelling
Framework (GMF) has been developed.

Having said that, there are gaps that these components have
not addressed, and these gaps become apparent when it comes
to managing the dependencies of a component. If the developer wishes to manipulate the dependencies, he/she has to
revert back to the conventional method and go and edit the
text file containing the list of dependencies.

IV. IMPLEMENTATION DETAILS
The implementation of the following concept can be understood through the following points • Create an in-memory model of plug-in workspace
• Visualise it using GMF
• Add / Delete / Modify dependencies using GMF
• Changes to in-memory model
• Reflect the changes back to the code (Automated code
generation)

V. VALUE PROPOSITION
* Visualisation of bundle & its dependencies
In a complex dependency scenario involving hundreds of
plug-ins, visual representation of these dependencies would
make maintaining and editing of these dependencies more
easier.
* Improved usability and maintainability
Allowing the runtime to modify the code (automatic code
generation/ modification ) reduces manual errors.
Auto code generation can be controlled to ensure best practices.
* Pluggable
The implementation is eclipse based. So it can be packaged
as a plug-in and made available to developers.
* Portable
The plug-in generated can be ported to any other IDE that
supports eclipse / plug-in based architecture.
